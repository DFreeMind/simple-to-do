# 数据模型

## 作用与权威来源

本文件描述前端与 Rust 层交换的**应用状态契约**，用于新增功能和兼容旧数据。SQLite 的物理列、索引与附件目录以 [数据库设计](数据库设计.md) 和 `src-tauri/src/main.rs` 为准；本文件不重复记录一次性历史方案。

当前前端状态版本为 **v13**。应用保存时，Pinia 将状态组合为一个 payload，Rust 再拆分写入关系表。

## 根状态

```ts
type AppState = {
  schemaVersion: number
  groups: Group[]
  lists: List[]
  taskGroups: TaskGroup[]
  tasks: Task[]
  trash: Task[]
  listTrash: ListTrash[]
  viewOrders: Record<string, string[]>
  profile: Profile
  settings: Settings
  clock: Clock
}
```

`schemaVersion` 用于前端状态兼容；缺失字段由迁移器和 normalize 补默认值。`trash` 与 `listTrash` 是产品层回收站状态，不等于 SQLite 表的删除标记。

## 核心实体

| 实体 | 关键字段 | 约束 |
| --- | --- | --- |
| Group | `id`、`name`、`collapsed`、`sortOrder` | 侧栏清单分组 |
| List | `id`、`name`、`groupId`、`color`、`viewMode`、`sortOrder` | `viewMode` 为 `list` 或 `group` |
| TaskGroup | `id`、`listId`、`name`、`emoji`、`color`、`sortOrder`、`collapsed` | 必须属于一个现存清单 |
| Task | `id`、`title`、`listId`、`completed`、`deleted`、`dueDate`、`reminderAt`、`repeatRule`、`priority`、`tags`、`subtasks`、`attachments` | `taskGroupId` 非空时必须与任务同属一个清单 |
| Subtask | `id`、`title`、`completed`、`sortOrder` | 通过任务嵌套保存，按排序显示 |
| Attachment | `id`、`kind`、`mime`、`originalName`、`relativePath`、`sha256`、`sizeBytes` | 产品当前只创建 `image`；预览 URL 仅存在运行时 |
| Profile | `id`、`nickname`、`avatarRelativePath`、`avatarSha256` | 是当前设备资料，不是云账号 |
| Settings | 外观、布局、已完成显示、通知、音效、窗口关闭和启动提示偏好 | 新增字段必须给默认值 |
| Clock | `profiles`、`focusSettings`、`activeSession`、`pendingBreak`、`cycleFocusCount`、`history`、`rhythm`、`garden` | 专注模式、休息节奏、未结束会话、历史、节律提醒和专注花园 |
| FocusProfile | `id`、`name`、`durationSeconds`、`description`、`sortOrder` | `durationSeconds` 为 `null` 时表示自由计时 |
| FocusSession | `id`、`profileId`、`taskId`、`status`、`phase`、`durationSeconds`、`createdAt`、`startedAt`、`elapsedSeconds`、`timeline` | `phase` 为 `focus`、`short-break` 或 `long-break`；`status` 为 `running` 或 `paused`；新会话的 `timeline` 记录开始、暂停、继续、调时、换任务和结束事件 |
| PendingBreak | `phase`、`profileId`、`durationSeconds`、`createdAt` | 专注完成后等待用户开始或跳过的短/长休息，不计入运行会话 |
| FocusHistory | `id`、`profileId`、`taskId`、`taskTitle`、`phase`、`startedAt`、`finishedAt`、`elapsedSeconds`、`result`、`reward`、`note`、`timeline` | 新完成记录以专注花园承接成长反馈；`reward` 仅兼容旧果实奖励。`timeline` 保存可展开的过程明细，旧历史缺少时间线时保留为空 |
| Rhythm | `pausedUntil`、`reminders`、`history` | 全局暂停状态、可同时运行的节律提醒集合和独立处理历史 |
| RhythmReminder | `title`、`enabled`、`triggerType`、`intervalSeconds`、`time`、`weekdays`、`workStart`、`workEnd`、`quietStart`、`quietEnd`、`cycleStartedAt`、`nextDueAt`、`manualCycleStartedAt`、`pendingSince`、`lastResolvedAt`、`lastCompletedAt`、`snoozedUntil`、`skippedDate`、`activitySeconds`、`breakThresholdSeconds` | `interval` 使用持久化倒计时；`fixed-time` 使用下一个固定时刻；`active-duration` 只累计连续电脑活跃时间，达到真实离席阈值才自动重置，并且只有原生活跃时长能力可用时允许启用。`manualCycleStartedAt` 仅表示用户在常规时段外主动开启的当前一轮，完成或跳过后恢复原有运行时间。 |
| RhythmHistory | `id`、`reminderId`、`reminderTitle`、`triggerType`、`triggerLabel`、`triggeredAt`、`resolvedAt`、`action`、`responseSeconds`、`snoozeMinutes` | 每次提醒处理独立追加；保留提醒名称和规则快照，避免配置变化后历史失真 |

专注历史和节律历史分别最多保留最近 5000 条。回顾界面按 25、50 或 100 条分页渲染；筛选和排序在当前日期范围内执行，不改变本地原始历史顺序。

## 专注花园

v13 在 `clock.garden` 中保存花园状态。`settings.clockView` 的合法值包含 `achievement`，与 `focus`、`rhythm`、`history` 平级；“花田总览 / 花种图鉴 / 成长徽章”是专注成就页的二级视图，不写入全局模块状态。

```ts
type FocusGarden = {
  startedAt: string
  dailyGoalMinutes: number
  selectedSpeciesId: string
  nextSpeciesId: string | null
  longestSessionMinutes: number
  days: GardenDay[]
  achievements: GardenAchievement[]
}

type GardenDay = {
  date: string
  speciesId: string
  goalMinutes: number
  growthMinutes: number
  stage: 'seed' | 'sprout' | 'leaves' | 'bud' | 'opening' | 'bloom'
  finalizedAt: string | null
}

type GardenAchievement = {
  id: string
  unlockedAt: string
  progressValue: number
}
```

- 花种名称、`collectionId`、介绍文案、场景光线与地景色、程序化株型、花盆样式、动画节奏、模块化 WebP 素材、解锁门槛和无障碍说明属于随应用发布的静态目录，不把素材路径、渲染引擎、花盆参数或动画状态写入用户数据；用户数据只保存稳定的 `speciesId`。目录当前包含 12 个稳定 ID，替换素材、花盆、骨架或扩充目录不升级用户数据版本。
- `GardenDay` 保存当日目标与花种快照，避免用户以后修改目标或默认花种导致历史外观改变。`growthMinutes` 只累计结果为 `completed`、阶段为 `focus` 的实际有效分钟。
- 历史日会在进入下一自然日时写入 `finalizedAt`；长期花田不依赖 5000 条专注历史的保留上限。删除今天的单条专注记录会重算今日成长，已经归档的历史花田不倒退。
- 徽章解锁结果单独保存，使已取得的非连续里程碑不会因历史保留上限回退；`progressValue` 保存解锁时的数值证据。规则升级不得撤销已解锁徽章。
- “半园花色”和“十二花境”分别在实际培养 6 种、12 种花时写入 `achievements`。专注结算返回的 `unlockedSpeciesIds` 只用于当次解锁演出，不写入本地模型；它由结算前后累计门槛差异生成，因此普通重复结算不会重复播放。
- 旧 `FocusHistory.reward` 保持可空兼容；花园实施后新记录不要求写入果实奖励。迁移不得把蓝莓等旧收获自动换算成花园天数。

## 任务字段语义

- `myDayDate`：任务加入哪一天的今日视图，格式为 `YYYY-MM-DD`。
- `dueDate`：带可选时间的截止日期；`reminderAt` 是独立提醒时刻，`reminderDisabled` 表示用户明确关闭提醒。
- `repeatRule`：当前支持 `daily`、`weekdays`、`weekly`、`monthly`、`yearly`。
- `descriptionHtml`：富文本备注 HTML。嵌入图片保存为应用附件的相对路径，而不是 base64。
- `deletedByListId`：清单被删除时，用于将任务与原清单回收站关联并支持一起恢复。
- `comments`、`editorMode`：仅为历史数据兼容保留，当前界面不提供评论或编辑模式切换。

## 设置的稳定字段

`theme`、`themeBackgrounds`、`density`、`sidebarCollapsed`、`detailOpen`、`detailWidth`、`startView`、`completedVisible`、`groupCompletedDisplayMode`、`groupCompletedVisibleByDefault`、`groupCompletedVisibility`、`showCompletionDuration`、`trashRetentionDays`、`soundEnabled`、各分类音效开关、任务与节律提醒通知及声音开关、`focusCompletionNotificationsEnabled`、`focusCompletionSoundEnabled`、`focusReminderAlwaysOnTop`、`focusControllerAlwaysOnTop`、`focusControllerStyle`、`windowCloseBehavior`、`dailyGuidanceEnabled`、`dailyGuidanceStyle`。`groupCompletedVisibility` 以“清单 + 分组”为键保存已完成任务的显示状态；旧数据默认沿用 `groupCompletedVisibleByDefault`。三个专注完成偏好与桌面控制器置顶偏好对旧数据默认均为 `true`；控制器置顶和完成提醒窗置顶相互独立，不关闭应用内完成反馈。

`focusControllerStyle` 的合法值为 `orbit`、`island`、`classic`。新安装默认 `orbit`；v13 及更早数据迁移到 v14 时写入 `classic`，避免升级后正在使用的控制器突然改变外形。专注岛是否展开属于瞬时界面状态，不持久化。

新设置必须：提供默认值、在旧状态 normalize 时补齐、确认是否要持久化，并同步更新设置界面、应用内帮助和产品说明。

## 兼容与迁移规则

1. 前端状态迁移由 `src/utils/migrator.js` 完成；目前兼容 v1–v13 状态。迁移前会创建迁移备份。
2. SQLite 结构迁移由 Rust 管理，使用独立的 `databaseSchemaVersion`；不得以修改前端 `schemaVersion` 代替表结构迁移。
3. 读取到未来版本、字段关系不合法或数据库不可读时，停止自动保存并显示保护错误，不能落回空数据。
4. 新字段优先可空或有安全默认值；删除字段前必须提供向后读取策略。
5. 任务与清单删除先进入回收站。附件引用移除后不会立刻删除物理文件，而是通过用户触发的扫描与清理站处理。
